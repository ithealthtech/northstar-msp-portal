Troubleshooting

Most access problems trace back to one thing: identity is not authorization. Start here.

Symptom finder

Search troubleshooting

Type a symptom, an environment variable, or an error code.

A valid Entra user signs in but sees nothing

This is the expected result for an unprovisioned user. Northstar does not create users just-in-time from an email address or a company claim.

Provision the Entra tenant/object pair first — see provisioning. Confirm the database identity is active and has either a client membership or an MSP platform assignment.

An MSP administrator cannot see all clients

By design. An MSP role does not implicitly grant the whole portfolio. Either set PORTAL_PLATFORM_SCOPE=all for that identity, or assign their clients explicitly in msp_company_scopes.

A client user gets 404 for a record that exists

Also by design. When a client user requests a resource belonging to another company, Northstar returns not-found rather than forbidden, so the response does not confirm that the other company's record exists.

If the user should have access, check their company membership rather than the record.

The demo role buttons are missing or ignored

Preview roles only work under file:// or an explicitly enabled, unconfigured local demo. Once Entra is configured, preview buttons and saved preview roles are ignored entirely.

For the local demo, set DEMO_MODE=true and SEED_DEMO_DATA=true in .env.local and serve from 127.0.0.1. The demo authorization header is rejected for non-loopback callers.

Production refuses to start

Production startup rejects DEMO_MODE=true outright. Check that DEMO_MODE, SEED_DEMO_DATA, and SIGNATURE_ALLOW_DEFAULT_ADMIN are all disabled.

Readiness also stays blocked until backup evidence exists — that is intentional, not a failure. npm run startup:production exercises exactly this path.

An API call returns 405 with an Allow header

The path exists but the method is not supported on it. The Allow header lists what is. Unknown paths return a JSON 404 instead.

ConnectWise synchronization fails or is rate-limited

Confirm CONNECTWISE_CLIENT_ID and CONNECTWISE_CLIENT_SECRET are configured together, and that CONNECTWISE_BASE_URL is the correct regional endpoint from .env.example — production rejects non-ConnectWise origins.

The server honors vendor quota headers and records rate-limited and failed runs. Check the integrations view or the audit log for the recorded run rather than retrying blindly.

A module is visible in demo but missing in production

Production navigation release-gates modules without released server APIs. Explicit demo mode retains those design prototypes without representing them as operational integrations. See the current boundary on the overview.

Still blocked?

Open a reproducible issue.

Include the version, runtime, whether Entra is configured, the exact route and method, and the request ID from the response. Never include customer data, credentials, tokens, databases, exports, or production screenshots. Use a private advisory for a suspected vulnerability — not a public issue.
